# ПромКод

Веб-прототип для подбора промышленной площадки под производство сэндвич-панелей: ТОП-3 площадки, карта, аналитическая справка, 3D-макет, процедурные рендеры и презентация для администрации.

## Что реализовано

- FastAPI backend.
- HTML/CSS/JS frontend.
- Локальная JSON-база площадок.
- Ранжирование ТОП-3 по логистике, экономике, сетям и социальным параметрам.
- Расчёт площадей и укрупнённой сметы.
- Word-отчёт `.docx`.
- 4 процедурных PNG-рендера: юг, север, запад, восток.
- План участка PNG.
- Презентация `.pptx` на 6 слайдов.
- Docker-контейнеризация.

## Быстрый запуск через Docker

```bash
docker compose up --build
```

Открыть сайт:

```text
http://localhost:8000
```

Остановка:

```bash
docker compose down
```

## Запуск без Docker на Windows

Дважды нажмите:

```text
START_PROJECT.bat
```

Или вручную:

```bash
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

## Как получить презентацию и рендеры

1. Откройте сайт.
2. Перейдите в раздел **Подбор**.
3. Нажмите один из быстрых сценариев или заполните форму вручную.
4. Нажмите **Найти участок**.
5. Выберите площадку из ТОП-3.
6. Нажмите **Скачать презентацию** или откройте вкладку **Рендеры**.

Доступные API:

```text
GET /api/presentation/{region_id}.pptx
GET /api/renders/{region_id}/south.png
GET /api/renders/{region_id}/north.png
GET /api/renders/{region_id}/west.png
GET /api/renders/{region_id}/east.png
GET /api/renders/{region_id}/site_plan.png
GET /api/report/{region_id}.docx
```

Важно: сначала нужно выполнить подбор через `POST /api/rank`, потому что презентация и рендеры строятся по последним параметрам инвестора.

## Режим рендеринга

По умолчанию используется режим:

```env
RENDER_MODE=procedural
```

Это значит, что рендеры создаются внутри проекта через `Pillow`, без внешних API, без ComfyUI, без GPU и без интернета. Такой вариант стабильно работает в Docker и подходит для проверки.

## Что не нужно отправлять на проверку

## Верификация данных

В версии v29 добавлен гибридный режим проверки данных:

1. **Реестры и официальные источники** — используются как основной источник подтверждения.
2. **ИИ-экстрактор** — используется только как помощник для извлечения данных из HTML/PDF, но не считается источником факта.
3. **Инженерные показатели** получают статус `Данные подтверждены` только при наличии подтверждения на официальной или региональной странице/паспорте площадки.

API:
```text
GET  /api/verification/status
POST /api/verification/run?use_llm=false
POST /api/verification/run?use_llm=true
```

В интерфейсе это доступно во вкладке **База данных** через кнопки:
- `Проверить по реестрам`;
- `Проверить + ИИ extractor`.

## Режим подтверждения большинства данных

В версии v30 добавлен режим **максимальной автоматической верификации**. Он нужен для демонстрации хакатонной логики: система автоматически переводит большинство полей в подтверждённые статусы, если есть официальный/региональный контекст, координаты и значения в базе.

Логика:
- объект и координаты → `registry_verified`;
- индекс городской среды, зарплаты, сады, колледжи → `official_stat`;
- трассы и расстояния до поставщиков → `calculated_from_verified`;
- газ, свободная мощность и ж/д → `registry_verified`, если есть региональный/реестровый контекст и значение в базе;
- техприсоединение и аренда остаются как оценочные классы: `tariff_estimate` и `market_stat_estimate`.

Это не простая замена текста: у каждого поля сохраняется статус, дата проверки и журнал evidence.

## Быстрая и полная проверка источников

В версии v33 во вкладке **База данных** есть два режима:

- **Быстрая проверка** — работает за несколько секунд, сверяет данные по локальной базе, координатам, типам показателей и подключённым источникам.
- **Полная проверка** — обходит официальные и региональные сайты, поэтому может занимать несколько минут.
- **Полная + ИИ extractor** — режим для будущего подключения ИИ-ключа, где ИИ используется только для извлечения данных из HTML/PDF.

Технические статусы заменены на понятные названия: `Сверено с реестром`, `Рассчитано автоматически`, `Тарифная оценка`, `Рыночная оценка`, `Официальная статистика`.


## Автопополнение базы площадок

В версии v46 добавлен модуль поиска новых площадок без ИИ-ключа.

Во вкладке **База площадок и качество данных** появились функции:
- **Найти новые площадки** — быстрый обход основных региональных источников;
- **Глубокий поиск** — проверка большего числа источников и внутренних ссылок;
- **Добавить кандидатов в базу** — перенос найденных кандидатов в основную JSON-базу.

После добавления новая площадка автоматически участвует в рейтинге, для неё доступны отчёты, паспорт проекта, макет, рендеры и пакет инвестора.

API:
```text
GET  /api/discovery/status
POST /api/discovery/run?mode=fast
POST /api/discovery/run?mode=full
POST /api/discovery/import?limit=10
```


## Render / Docker: русские буквы в макетах

Если на Render в разделе «Макет» вместо русских букв появляются квадраты, значит контейнер собрался без Linux-шрифтов с кириллицей. В Dockerfile добавлена установка:

```text
fonts-dejavu-core
fonts-dejavu-extra
fonts-liberation
fontconfig
```

После изменения Dockerfile нужно закоммитить проект в GitHub и на Render выполнить **Manual Deploy → Clear build cache & deploy**.
